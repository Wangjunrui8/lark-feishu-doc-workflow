# 周报模板

## 输出格式：六段式周报

周报文档采用飞书云文档格式（XML），包含以下六个章节。第一个章节「本周概览」用 callout 卡片呈现，后五个为固定正文章节。

---

## 模板结构（含颜色标注）

在飞书 XML 中，使用 `<span text-color="颜色">` 实现颜色标注。颜色映射规则见下方「颜色规则」。

```
# YYYY年MM月DD日 - YYYY年MM月DD日 工作周报

## 📋 本周概览（callout 卡片）
本周概览：共跟踪 24 项需求，其中 3 项本周上线发布（能源盒子邀约下发、南向通用化改造迭代一、赛意-渠道客户系统），7 项进入测试阶段，6 项持续开发中，5 项待排期。完成 vpp 项目主干合入与基线发布，参与基准价改造方案评审，推进线损与日清算设计验收问题整改。完成 Q3 OKR 制定，发布 AI 智能周报到 Aily 技能市场并编写配套文档。

## 一、本周工作

### 业务子域A
- **需求名称**（🔴 P0）：✅ 已发布上线，完成XX功能
- **需求名称**（🔴 P0）：🟠 开发中，进度 80%
- **需求名称**（P1）：🔵 测试中，进度 85%

### 业务子域B
- **需求名称**（P2）：🔵 联调中，进度 50%
  - 相关文档：《技术方案文档》—— 方案要点摘要

### 文档沉淀
- **《文档标题》**：核心要点摘要（未能关联到具体需求的独立文档产出）

## 二、下周计划

### 业务子域A
- **计划任务**（🔴 P0）：预计完成目标
- **计划任务**（P1）：预计完成目标

## 三、需要协调和帮助

- **事项描述**：需要XX部门/XX同事协助解决XXX问题

## 四、风险与策略

- **风险描述**（🔴 P0）：XX需求进度滞后，当前进度30%，预计下周难以按期交付。**策略**：协调前端资源支援，调整排期优先级
- **风险描述**（P1）：XX需求依赖后端接口，接口尚未联调完成。**策略**：与后端团队确认接口交付时间，先用 Mock 数据推进前端开发
- **风险描述**（P2）：XX需求技术方案尚未确定，存在选型风险。**策略**：本周内组织技术评审，确定方案后立即启动开发

（注：如本周无风险项，写"本周无显著风险"）

## 五、建议

### 能力提升建议
- **能力方向**：基于本周工作中的具体场景，建议提升的方向及预期收益

### 解决问题带来的价值
- **解决的问题**：对业务/团队/效率的实际影响和产出价值
```

## 颜色规则（XML 实现）

### 优先级颜色
- **P0**：红色加粗 → `<span text-color="red"><b>P0</b></span>`
- P1/P2/P3：不加颜色，正常显示为 `(P1)` / `(P2)` / `(P3)`

### 需求状态颜色
| 状态 | 颜色 | XML 写法 |
|------|------|----------|
| 已发布上线 / 已完成 | 绿色 | `<span text-color="green">已发布上线</span>` |
| 测试中 | 蓝色 | `<span text-color="blue">测试中</span>` |
| 开发中 | 橙色 | `<span text-color="orange">开发中</span>` |
| 待发布 | 橙色 | `<span text-color="orange">待发布</span>` |
| 待处理 / 待启动 / 待排期 | 灰色 | `<span text-color="gray">待排期</span>` |
| 暂停 | 红色 | `<span text-color="red">暂停</span>` |
| 废弃 | 灰色 | `<span text-color="gray">废弃</span>` |
| 临时 | 灰色 | `<span text-color="gray">临时</span>` |
| 阻塞 / 延期 | 红色 | `<span text-color="red">阻塞</span>` |
| 联调中 | 蓝色 | `<span text-color="blue">联调中</span>` |

## 各章节数据来源与生成规则

### 本周概览（callout 卡片）

**呈现方式**：使用 `<callout emoji="📋">` 块，作为文档正文第一个元素（紧跟 `<h1>` 标题之后）。**保持精简，2-3 句话概括，不做罗列**。

**内容要求**：
- 一段连续文字写在 callout 内的一个 `<p>` 标签中，不使用列表（`<ul>` / `<ol>`）
- 第一句：需求总数 + 关键状态分布（上线发布列出具体名称，其余状态只说数量）
- 第二句：其他重要完成事项（从飞书任务、消息、文档中提炼非需求跟踪表内的事项，用顿号或逗号串联，不逐条展开）

**数据来源**：
- 需求统计：Step 2.1 + Step 2.5 合并去重后的多维表格记录
- 其他完成事项：飞书任务、飞书消息、本周创建的文档中不属于需求跟踪表内的事项

### 一、本周工作

**数据来源**：
- 大前端项目信息共享表：当前用户负责的待排期、开发中、测试中、待发布、暂停、废弃、临时状态的项目，以及本周上线的已发布项目
- 飞书任务：本周已完成的任务
- 飞书消息：本周关键讨论和决策
- 本周创建的文档：有实质内容的文档，按关联性分配到对应业务子域或「文档沉淀」分组

**生成规则**：
1. 按**业务子域**分组展示项目需求进展，**每个子域只标注一次作为标题**（如 `### 用户增长`），其下汇总所有该子域的条目
2. 每条包含：需求名称、进度百分比、状态变化
3. 每条需求**必须标注优先级和状态，并应用颜色规则**（P0 标红，状态按颜色表标注）
4. 按任务等级（P0 > P1 > P2）排序
5. **文档关联**：能关联到已有需求的文档，作为子条目附在对应需求下方（如"相关文档：《XX方案》—— 要点摘要"）；无法关联的文档归入末尾的「文档沉淀」分组

### 二、下周计划

**数据来源**：
- 大前端项目信息共享表：待排期和开发中的需求
- 飞书任务：截止日期在下周的任务

**生成规则**：
1. 按**业务子域**分组，**每个子域只标注一次作为标题**，其下汇总该子域所有计划条目
2. 每条包含：预计目标或里程碑
3. **标注优先级，P0 标红**

### 三、需要协调和帮助

**数据来源**：
- 大前端项目信息共享表：状态为"阻塞"或"延期"的需求
- 飞书消息：讨论中提到的卡点和依赖

**生成规则**：
1. 列出具体阻塞事项
2. 说明阻塞原因
3. 明确需要的支持（哪个团队/哪个人协助什么）
4. 如无阻塞项，写"本周无需要协调事项"

### 四、风险与策略

**数据来源**：
- 大前端项目信息共享表 + 信息收集表：进度滞后的需求（开发中但进度明显低于预期）、依赖外部方的待发布需求、技术方案尚未确定的开发中需求
- 飞书任务：截止日期临近但未完成的任务
- 飞书消息：讨论中提到的技术风险、资源冲突、排期冲突

**生成规则**：
1. 每条包含：**风险描述**（加粗）+ 优先级 + 具体风险点 + **策略**（加粗）+ 应对措施
2. 风险按严重程度排序（P0 > P1 > P2）
3. 策略必须具体可执行，不能空泛（如"协调XX资源""本周内组织XX评审"）
4. 常见风险类型：进度滞后、外部依赖未就绪、技术方案未定、资源冲突、排期冲突
5. 如无风险项，写"本周无显著风险"

### 五、建议

**数据来源**：
- **本周创建的文档（核心来源）**：逐篇读取文档正文，提取核心方案、技术决策、架构设计、方法论沉淀等关键要素；文档中的技术方案和创新思路直接作为"能力提升建议"的素材，文档解决的实际问题直接作为"解决问题带来的价值"的素材
- 本周日常沟通（IM 消息、会议）：识别协作中的痛点、效率瓶颈、技术难题
- 本周完成的任务和需求：分析解决过程中的技术挑战和方法论

**生成规则**：

本章节需从本周实际工作内容中**深度挖掘**，而非泛泛而谈。包含两个子板块：

1. **能力提升建议**
   - 从本周工作中识别技术挑战或暴露的能力短板
   - **优先从本周创建的文档中提炼**：文档涉及的技术方案、架构设计、方法论总结，反映了当前团队关注的能力方向，据此给出深化建议
   - 每条建议包含：具体能力方向 + 为什么需要提升（本周哪个场景暴露了短板 / 哪篇文档体现了该方向）+ 提升后的预期收益
   - 基于本周文档和沟通中的真实事例，不要空泛建议
   - 示例："深入掌握 WebSocket 实时通信优化——本周 IM 消息推送模块遇到高并发断连问题，提升后可降低重连率 30%"

2. **解决问题带来的价值**
   - 从本周已完成的工作中提炼解决的具体问题
   - **优先从本周创建的文档中挖掘**：文档中记录的技术方案落地、问题解决过程、性能优化成果等，是价值量化的一手素材
   - 每条包含：解决了什么问题 + 该问题对业务/团队/效率的实际影响 + 可量化或可感知的价值
   - 优先选取有明确产出、可衡量影响的事项
   - 示例："解决了数据看板加载超时问题，页面首屏加载从 8s 降至 2s，用户体验显著提升"

**关键原则**：
- 必须基于本周文档产出和沟通记录中的真实事件，禁止泛泛而谈
- 如无本周文档产出，则从任务完成情况和沟通记录中挖掘
- 拒绝流水账，聚焦"价值"和"成长"两个维度

## 文档创建参数

- **输出位置**：飞书云文档「我的空间」根目录
  - 使用 `lark-cli docs +create` 直接创建（不传 `--folder-token` 即默认存放到「我的空间」根目录）
  - 创建后返回文档 URL，用于最终交付
- **文档标题**：`YYYY年MM月DD日-MM月DD日 工作周报`（使用本周一和周日日期）
- **文档格式**：使用 XML 格式创建（`--doc-format xml`），以获得更丰富的排版效果（callout、grid、checkbox 等富 block）
